# ADR 0002：通过 HTTP 商户接口接入支付中心并分离售卖方案

- 状态：已接受
- 日期：2026-08-11

## 背景

项目需要提供激活码购买和订阅续费，但 `wxpay-payment-center` 是独立部署的支付中心，使用商户签名请求和签名回调。管理员还需要在不重启进程的情况下维护任意数量的时长/价格方案。

## 决策

1. 通过 `internal/paymentcenter` 的 HTTP Adapter 对接支付中心，不引入支付 SDK，也不把支付中心的 JSON/签名细节散落到 Web Handler。
2. 在 SQLite 中新增 `payment_plans`、`payment_orders` 和 `payment_events`：
   - 方案只影响新订单；
   - 订单保存名称、天数、分钟数、金额和币种快照；
   - 支付事件以事件 ID 幂等。
3. 支付中心的 `app_id`、`secret`、地址、回调地址、可选支付后跳转地址和订单有效期由管理员设置页配置。支付后跳转地址按订单创建请求传给支付中心，支持 `{token}`、`{order_no}` 和 `{merchant_order_no}` 占位符；App Secret 使用现有凭据主密钥加密保存。
4. 付款回调先验证原始请求体 HMAC、时间戳、nonce、应用 ID、订单号、金额和币种，再在本地事务中完成履约：
   - 激活码方案生成一个一次性邀请码；
   - 续费方案绑定下单时通过用户名/密码验证的业务账号，并延长现有到期时间。
5. Emby 状态恢复继续写入现有 `emby_access_sync_jobs`，支付回调不在 SQLite 事务中调用外部 Emby 或支付中心。
6. 除签名回调外，后台定期查询支付中心的待支付订单，以补偿回调延迟或丢失。

## 后果

- 支付中心需要先创建商户应用，并把本项目 `/webhooks/wxpay-payment-center` 回调地址配置到该应用。
- 已创建订单不会因为管理员修改方案而改变金额或时长。
- 续费付款前必须验证账号密码；本地订单只保存账号 ID/用户名快照，不保存这次提交的明文密码。
- 当前支付中心首版没有退款/拒付流程；这类订单需要后续人工审核或另行设计权益撤销规则。
